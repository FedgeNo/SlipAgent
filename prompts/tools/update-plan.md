# `update_plan`

Break complex work into manageable tasks and track them here. Treat work as complex when it needs several distinct actions, touches several files or components, or will span many turns; simple requests need no plan. Make each task a concrete step you can finish and verify within a few tool batches, and split a task further when it proves larger than expected. Prefer this tool to a plan held only in replies or reasoning.

The plan persists the objective, stages, evidence, and next actions. Update it as work changes: mark a stage in progress before starting it, and complete it with its evidence as soon as it is done. The latest successful plan survives history compression and resume; continue from it, subject to current user instructions. An update counts only once its result confirms success.

Use 1–8 outcome-based stages, at most one in progress. State what each stage must establish. Cite observed evidence for completed stages; leave evidence empty when unavailable. The plan records your interpretation of user instructions and proposed work.

Phrase pending work prospectively, current work as in progress, and completed work and evidence in past tense. Short task labels are sufficient with a status. Keep future steps conditional on unknown results.
