# Command Monitoring Setup

No command monitor is initialized in this process. Monitoring is optional: use it when waiting for a background job's output or completion would otherwise require repeated polling. If needed, load the definition with `load_tools` using `{"names":["monitor_command"]}`. Start the job with `run_command` and `background=true`, then use its returned `job_id` to initialize a monitor with `monitor_command` and `{"action":"start","job_id":"ID_FROM_RESULT","pattern":"ready","timeout":120}`. The pattern is a case-sensitive literal substring, not a regular expression. Omit `pattern` to wait for job completion. `repeat=true` watches repeated matches until the job ends or the monitor expires; the default completes on the first match.

Start returns a `monitor_id` and records this initialization turn. The watch replays up to the last 65,536 retained UTF-8 bytes of each stream, then observes new output; omitted earlier bytes are reported. The active watch and its results are supplied in subsequent request prompts, including the result itself when ready. Do not repeatedly poll an active watch. You may continue independent authorized work or use `action="wait"` with its `monitor_id` for a bounded wait of at most 30 seconds. Monitoring does not create new model requests or restart a finished agent. Watches last at most 600 seconds (default 30) and never extend the command's execution timeout. They survive compatible code reloads but do not reattach after process restart or session replacement. Do not assume historical watches are still active.
